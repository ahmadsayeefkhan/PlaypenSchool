# The Playpen School: website

The website of The Playpen School, Dhaka (https://playpen-school.vercel.app), made by Defined Solution. A static site of **43 pages** (the home and 42 inner pages, plus 13 redirect stubs for the old flat pages): plain HTML, one stylesheet per layer, one small script for the inner pages, no framework, no CDN, no third-party script. `site/` is the whole published folder (Vercel serves it from `main`; GitHub Pages also works from a sub-path). One page is not built: P03, "Welcome from the Principal", which needs the Principal's own words (`docs/CONTENT-TO-CONFIRM.md`, A2).

```
site/            the published folder
  index.html       the home (hand-built: cover, sheets, the Ascent scene, the ledger). Never written by the build.
  <section>/...    every other page, written by the build as <slug>/index.html
  404.html         the page-not-found page (absolute URLs, so it works at any depth)
  about.html ...   meta-refresh stubs for the old flat pages (about.html, academics.html ...), pointing at the new pages
  css/main.css     tokens, type, the home, the header, the full-screen menu, the footer
  css/pages.css    the inner-page components (hero, prose, fact strip, cards, accordion, timeline, forms ...)
  css/pages-additions.css  GENERATED from build/additions/*.css (one file per page group); never edit
  js/inner.js      inner-page behaviour (menu, reveals, accordion, filters, lightbox, forms, search); js/main.js + js/sections/ run the home
  js/pages-additions.js    GENERATED from build/additions/*.js; never edit
  assets/          media (graded photographs), img (school photographs), brand, logo, 3d; search-index.json, sitemap.json
  vendor/          fonts (Newsreader, Hanken Grotesk) and the libraries the home uses
  sitemap.xml, robots.txt   GENERATED by the build
build/           the generator (Python 3, standard library only)
  nav.json         the information architecture: every page, the menu, the footer, the phone lines, the redirects
  pages/           one source file per page: front matter + the body
  additions/       one <group>.css and <group>.js per page group: extra rules and behaviour, joined by the build
  build.py         python build/build.py            builds every page, sitemap.xml, robots.txt, search index, 404, redirects, vercel.json
  check.py         python build/check.py            crawls site/: links, anchors, H1, titles, alt, banned words, JSON-LD ...
  sync_home.py     python build/sync_home.py        copies the shell's menu, links, footer and SEO head into the home
  shell.py, media.py, htmlutil.py, images.py        the shell, the picture helper, HTML helpers, a crop tool
  dev/kit.html     the component kit (python build/build.py --kit, then /_kit/; never published, git-ignored)
  _old/            the previous generator, kept for reference
docs/            the documents (below)
brand/           the brand system (guidelines, logo files)
tools/serve.py   a local server with keep-alive and byte ranges
vercel.json      redirects from the old WordPress paths, cache and security headers (written by build.py; edit nav.json, not this file)
```

## Run it

```
python -I tools/serve.py 5180 --dir site          # then open http://localhost:5180/  (never file://)
python build/build.py                              # build everything
python build/check.py                              # verify the built site (add --strict before publishing)
python build/sync_home.py --check                  # is the home's generated menu, footer and head in step with nav.json?
```

While writing a section: `python build/build.py --only learning` and `python build/check.py learning`. A selector that matches no page is an error. In Git Bash write it without a leading slash (`--only admissions/faq`): Git Bash rewrites `/admissions/faq/` into a Windows path (the tools say so; `MSYS_NO_PATHCONV=1` switches the rewrite off). The page-writing contract, with every component as a copy-paste snippet, is `docs/COMPONENTS.md`.

Screenshots and the health report (console errors, overflow, broken images) come from the QA tools that sit next to this repository, not inside it (`../qa-tools/`): `node ../qa-tools/shot.mjs http://localhost:5180/about/ ../qa-tools/out/<group>/about --sizes=390x844,1366x768 --full`.

The built HTML is committed (the host serves `site/` as it is; there is no build step on the server). After changing `build/nav.json`, `build/shell.py` or a page source, run the build and commit `site/` with it. After changing `nav.json` or `shell.py`, also run `python build/sync_home.py`.

## Add or change a page

1. **List it.** Add an entry to `build/nav.json` `pages`: `id`, `slug` (with leading and trailing slash), `label`, `title`, `template` (T01 to T12), `parent`, `group` (the menu group), `menu` (true to list it in the full-screen menu), `footer` (a footer column key or null), `description` (60 to 170 characters, plain text) and `summary` (one line for cards and the sitemap). `nav.json` is the only place that says which pages exist: a link to a page that is not listed fails the build.
2. **Write it.** Create `build/pages/<slug>.html` (a hub is `build/pages/<slug>/index.html`): a front matter block, then the sections. Copy from the pilots (`build/pages/about/index.html`, `learning/elementary.html`, `admissions/faq.html`) and from `docs/COMPONENTS.md`. Never type a phone number, the hours or the address: use `{{phone:...}}`, `{{hours}}`, `{{address}}`. Link with `{{link:/slug/}}`, add photographs with `{{img ...}}` (only frames the catalogue allows), and put what the school must confirm in an `<!-- CONFIRM: ... -->` comment.
3. **Build and check.** `python build/build.py --only <section>`, then `python build/check.py <section>`. Fix every error and every warning you cannot explain.
4. **If it changes the menu, the footer or a label**, run the full `python build/build.py` and `python build/sync_home.py`, because every page carries the same shell and the home carries a copy of it between its `pp:begin` and `pp:end` comments.
5. **Look at it** at 390 px and 1366 px with `shot.mjs`, and with the keyboard.
6. **Record what is uncertain**: add a bullet to `docs/CONTENT-TO-CONFIRM.md` under the page, and a credit line to `docs/credits-log.md` for each new photograph.
7. **A new old-site redirect** goes into `nav.json` (`wordpress` for an old WordPress path, `redirects` for an old flat page), never into `vercel.json`.

A new component or behaviour goes into the page group's own `build/additions/<group>.css|.js` and is described in `docs/additions/<group>.md`; do not edit `site/css/pages.css` or `site/js/inner.js` for one page.

## How it fits together

- **One source of truth.** `build/nav.json` defines which pages exist, how they group, what the menu and footer show, the phone lines by section, the address, the redirects and the SEO descriptions. Nothing is typed twice.
- **One shell.** `build/shell.py` writes the head (canonical, Open Graph, Twitter, JSON-LD: School, WebSite, WebPage or FAQPage, BreadcrumbList), the skip link, the header, the menu, the breadcrumb, the hero, the footer and the phone bar for every page. All links and asset paths are relative, computed from the page's depth, so the site works from `/` and from a sub-path.
- **Fails loudly.** The build stops on an unknown link target, a missing asset, a missing or duplicate H1, a missing title or description, an unknown token or front matter key, a duplicate key, a bad date, broken tag nesting, an inline handler, a link that opens a new tab without saying so, a photograph the image catalogue flags (identifiable children). The checker then crawls the output: links, anchors, ARIA references, unknown classes and data attributes, banned words and exclamation marks (in the text, the alt texts and the meta tags), typed phone numbers, hours and addresses, outside addresses, a stale shell, empty pages, orphan files, the sitemap.
- **Parallel authors.** Page groups write only their own `build/pages/` sources and their own `build/additions/<group>.css|.js`; the build joins the additions into two generated files, so two agents never edit the same file.
- **Calm, factual, accessible.** English only; no invented facts (what the school must confirm is listed in `docs/CONTENT-TO-CONFIRM.md`); WCAG 2.2 AA; no exclamation marks and none of the banned words; forms are prototypes that say so and show the school's phone numbers (there is no mail server behind any form).
- **Defined Solution's own pages** (`site/credits.html`, `audit-report.html`, `report-summary.html`) sit in `site/`, are not linked from the school's pages, are disallowed in `robots.txt` and are skipped by the checker (`check.py --all` includes them). Whether they stay is a decision listed in `docs/CONTENT-TO-CONFIRM.md`, section 4.

## Publishing (Vercel)

The live site is https://playpen-school.vercel.app, a Vercel project connected to the GitHub repository `ahmadsayeefkhan/PlaypenSchool`, branch `main`. `vercel.json` already says everything the project needs (no framework, no install or build command, output directory `site`, `trailingSlash: true`), so a new Vercel project needs no settings: import the repository and deploy.

1. `python build/build.py --strict` and `python build/check.py --strict` must both print **no errors** (every page written, no draft stub). `--strict` also fails on warnings, and **three warnings are expected today**, each for a reason that is not a defect of a page:
   - `index.html [consent]`: the home uses nine photographs the catalogue marks as needing the school's consent (`docs/CONTENT-TO-CONFIRM.md`, A3). It clears when the school consents and the stems go into `docs/consent-cleared.txt`, or the frames are replaced.
   - `index.html [hours]`: the home's sample notice (a parent-teacher meeting, 9.00 am to 12.00 pm) carries hours that differ from the admissions hours. It clears when the sample notice is replaced by a real one (A7).
   - `gallery/index.html [weight]`: the checker estimates 3.6 MB because it counts the fallback JPG of every photograph. Measured in a browser (AVIF or WebP, lazy loading), the first view is about 0.7 MB and the whole page, scrolled to the end, about 2.0 MB.
2. `python build/sync_home.py --check` must say the home is in step.
3. Commit and push `main`. Vercel serves `site/`; `vercel.json` carries the redirects and headers (the photographs, brand files and 3D crest are cached for a day and re-checked, because their names are not content-hashed; only the vendored libraries are `immutable`). **A deploy at the root of a domain (Vercel) is built without `--base`.** Only a deploy under a sub-path (GitHub Pages at `/PlaypenSchool/`) needs `python build/build.py --base /PlaypenSchool/`, because `404.html` uses absolute URLs; every other page is relative and works either way.
4. After the deploy: open `/`, `/about/`, `/admissions/faq/`, `/sitemap/`, `/404.html` and an old address such as `/our-history/` (it should answer 301 to `/about/history/`); check `https://playpen-school.vercel.app/sitemap.xml` and `robots.txt`.
5. **Do not announce the site before `docs/CONTENT-TO-CONFIRM.md` has been read with the school**, at least section 1: the founding year, the Principal's letter, the photographs of children, the fee policy, the telephone lines and forms, the invented sample events on the home, the email addresses, and the legal check of /privacy/ and /terms/.
6. **Do not point `playpen.edu.bd` at this project** until the portal, the online payment page, the admission-form PDFs and the mission statement have a new address: the redirects would otherwise swallow the links that still point there (`docs/02-redirect-map.md`).
